# Review fixes — 20 October 2026

## Guest-facing changes

- The cabin date estimator no longer offers an Airbnb link for missing, past, reversed or insufficient-minimum dates. It uses the property date in Japan. Dates beyond the published rate schedule can still be checked on Airbnb, with no invented estimate.
- The prominent nightly-price strip includes the separate ¥7,000 cleaning charge per stay and taxes extra, in English, Japanese and Simplified Chinese.
- Equipment copy retains normal kitchen equipment but does not assert that larger induction-compatible cookware upgrades are installed in every cabin. The owner equipment confirmation remains open.
- All three privacy pages are dated 20 October, describe the current implementation and identify Airbnb as the active booking channel.

## Optional analytics

The device-time-zone filter is removed. All visitors now receive the same explicit accept/decline choice. Neither GTM/GA4 nor Metricool is requested until acceptance; advertising consent remains denied. Booking, contact links and the date checker do not require acceptance.

The choice is stored locally for 180 days. If browser storage is unavailable, acceptance applies to the current page only. Footer Analytics settings reopens the choice. Withdrawing consent disables GA4, deletes accessible first-party `_ga` cookies, clears a pending navigation measurement and reloads to unload already-loaded trackers. It cannot retract data already transmitted. The consent UI and privacy wording are available in all three website languages. There is no new GTM container import in this release.

Analytics reports will exclude visitors who do not accept. This is an intentional reporting change; do not interpret a drop in tracked users at deployment as proof that actual traffic dropped. Before accepting, ordinary clicks are not recorded retrospectively. If acceptance occurs on a cabin page, its current cabin view is recorded once.

## Release gate

The repository provides `npm run release:check` (build, then source checks), and the browser suite includes date-estimator interaction checks. GitHub Actions already rebuilds, checks that generated content matches Git and runs the browser suite.

**Owner dashboard step:** in Cloudflare Worker `kojohamawebsite` → Settings → Build → Build command, replace `npm run check` with `npm run release:check`. Leave the deploy command unchanged. This is a dashboard-only setting; committing this repository cannot change that setting. No Cloudflare account setting was changed during this code release.

Run `npm run release:check` and `npm run check:browser`, commit the generated pages and all supporting source changes, then deploy. Verify production separately after deployment.
